=== Introduction

This user manual will help you understand kafka Cost Control and how to use it propertly. This document assumes that you already have a running application. If not please see the <<section-installation>> section.

At this point you should have access to the Kafka Cost Control UI.

==== Graphql

Kafka cost control provides a graphql endpoint at: _<your-host>/graphql-ui_

In addition, there is a ready to use GraphQL UI. You can access it by going to the following URL: _<your-host>/graphql-ui_

==== Sign-in

Kafka Cost Control is either open to everyone or closed to everyone who hasn't signed in; there is no part in between. `CC_AUTH_MODE` decides how:

* `basic` (default): sign in as `admin` with the password in `CC_ADMIN_PASSWORD` (default `admin`, so set it).
* `oidc`: sign in through an OpenID Connect provider, e.g. Google, Microsoft Entra ID or Keycloak. The `admin` user still works with basic auth, for scripts such as the pricing-rule loader.
* `none`: no sign-in, for example when a proxy in front of Kafka Cost Control already authenticates every request. Everyone who reaches it can also change rules and start a reprocess.

The health (`/q/health`) and metrics (`/q/metrics`) endpoints stay open in every mode.

===== OpenID Connect

Register Kafka Cost Control as a web application (confidential client) at your provider, with the redirect URI `https://<your-host>/auth/callback`, and set:

[source,bash]
----
CC_AUTH_MODE=oidc
QUARKUS_OIDC_PROVIDER=google            # or QUARKUS_OIDC_AUTH_SERVER_URL=https://<issuer>
QUARKUS_OIDC_CLIENT_ID=<client id>
QUARKUS_OIDC_CREDENTIALS_SECRET=<client secret>
CC_AUTH_ALLOWED_DOMAINS=example.com     # who may sign in; comma-separated
----

`CC_AUTH_ALLOWED_DOMAINS` (and `CC_AUTH_ALLOWED_EMAILS` for single addresses) limits who gets in by the e-mail the provider confirms. Leave both empty only if the provider holds nobody but your own users: anyone with a Google or Microsoft account can sign in to a Google or Microsoft client.

The sign-in runs in the aggregator, so `/auth` must reach it on the same host as the UI, like `/graphql` (the Helm chart and the Kubernetes manifests route it). Behind a reverse proxy, the proxy must send `X-Forwarded-Proto` and `X-Forwarded-Host`, so the redirect URI uses the external address.
